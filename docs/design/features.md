# 機能一覧と、今回作らないもの

仕様書（`docs/spec.md`）とモックアップ（`mockup/`）を突き合わせ、クライアントの回答と、確認事項で決めたことを反映して整理したものです。

- **根拠**の列は、その機能を書いた箇所です。`spec 3-2` は仕様書の節番号、`channel-new.html` はモックアップのファイル名です
- 根拠が **mockup のみ**の項目は、仕様書に書かれておらずモックアップだけで決まっているものです（仕様書 §本書について に「見た目はモックアップが正」とあるため採用しています）
- **確認事項**の列は `questions.md` の番号です。**内容欄の文は、その番号の決定を反映済み**です。決まった経緯（クライアントの回答か、自分で決めたか）と、想定との違いは、`questions.md` の「回答と決定の記録」を見てください
- 画面の細部（項目・文言）は `screens.md`、権限とAPIの詳細は `permissions-api.md` に書きます。ここでは「何ができるか」だけを書きます
- **保留**: Q-15（1件のメッセージを削除したあとの本文の扱い）は決まっていません。F-15 に印を付けています

## 2. 今回作らないもの

### 2-1. クライアントが「作らない」「要らない」と書いたもの

| 作らないもの | 理由（クライアントの記載） | 根拠 |
|:--|:--|:--|
| 新着メッセージの自動表示（画面を開いたままで届く） | 今回は画面を開き直して確認できれば十分 | spec 4 |
| 通知（メール・スマートフォンへの通知） | まずは社内で使い始められる形を優先したい | spec 4 |
| 1対1のダイレクトメッセージ | チャンネルでの会話に絞りたい | spec 4 |
| ファイル・画像の添付 | 文章のやり取りに絞りたい | spec 4 |
| メッセージへのリアクション（絵文字を付ける） | 会話ができることを優先したい | spec 4 |
| 未読・既読の管理 | 同上 | spec 4 |
| 管理者による全体管理（利用者の停止、他人のチャンネルの管理） | 運用が固まってから考えたい | spec 4 |
| 書き込み・変更ができるAPI | 今回は要らない | spec 3-7 |
| スマートフォンでの表示（レスポンシブ対応） | 今回は考えなくてよい | spec 5-2 / design-guide.md §3 |
| 返信への返信（返信は1段まで） | 何段も重なると、どこに何が書いてあるのか分からなくなる | 回答 R-08 |
| チャンネルの作成者の交代 | 今回は交代できなくてよい | 回答 R-04 |
| 表示名・パスワードを変える画面 | 今回は要らない。必要になったら、あらためて相談する | 回答 R-13 |
| 登録の招待・承認 | 要らない。社内で使うものなので、メールアドレスがあれば登録できてよい | 回答 R-12 |
| チャンネル名・人の名前で探す検索 | 今回は要らない（検索はメッセージの本文だけ） | 回答 R-10 |

### 2-2. クライアントの記載はなく、確認事項で自分で決めて作らないもの

仕様書にもモックアップにも出てこないものを、確認事項で「作らない」と決めたものです。**クライアントが明示したものではありません**。クライアントが「作る」と言ったときは、機能一覧に F-26 以降として足します。

| 作らないもの | 決めた内容 | 確認事項 |
|:--|:--|:--|
| パスワードの再設定（忘れたとき） | 作らない。メール通知がスコープ外でメールを送れず、ログイン画面にも導線がない | Q-08 |
| アカウントの削除、登録時のメール確認 | 作らない。退職者のアカウントは残ったままになる | Q-09 |
| プライベートチャンネルのメンバーが自分から抜けること | できない。外せるのは作成者だけで、作成者は外れられない（作成者が外れられないことは回答 R-04） | Q-04 |
| 公開範囲（公開／プライベート）のあとからの変更 | 公開からもプライベートからも変えられない | Q-12 |
| チャンネル作成者による、他人のメッセージの編集・削除 | できない。仕様書が編集・削除を「自分が書いたメッセージ」に限っている | Q-05 |
| 削除したメッセージの復元 | 作らない。削除したメッセージの本文を、あとから誰も見られないものとするかは**保留**（チャンネル削除は、元に戻せない旨を示す） | Q-15（保留） |
